A local-first RAG toolkit that runs entirely on one PC.

mrag is an open-source command-line tool for building and operating a small RAG knowledge base on your own PC. Ingest business documents such as internal rules, manuals and specifications, build an index, and make them searchable from generative AI such as Claude Code and Dify. Documents, index and retrieval all stay local. Nothing is sent to the cloud.

Small, and quick to build

Four commands to learn. A folder of manuals or specifications for your own work becomes a searchable knowledge base the same day.

One PC, nothing leaves the building

Runs on Python, SQLite, Qdrant and Ollama alone. Qdrant runs in-process by default, so there is no server or container to set up. Documents, index and retrieval all stay on your PC, and embeddings and context generation use local models.

Grow it and bundle it when you need to

Check how documents were split, what context was added and why a result matched with mrag inspect and mrag eval, and switch retrieval strategies and chunking in YAML. When knowledge bases multiply, bundle them with mrag registry and let agents pick.

SQLite is the source of truth; Qdrant is a rebuildable vector index. In the default local mode Qdrant runs in-process, so no separate server is needed.

Four commands to a knowledge base.

Create a project, add documents, build the index, search. That's all.

mrag init my-kb --non-interactive
cd my-kb
mrag add /path/to/documents --recursive --include '**/*.md'
mrag index
mrag search "your query"
  1. 1
    init — create a projectGenerates mrag.yaml, a retrieval profile, kb_information.yaml and mrag.db. The Japanese tokenizer is detected automatically.
  2. 2
    add — register documentsRegister Markdown or text files one at a time or by directory. Preview the selection with --dry-run. Nothing is searchable yet at this point.
  3. 3
    index — build the indexSplits documents into chunks, computes embeddings with Ollama and writes them to Qdrant and SQLite FTS5. Later runs process only what was added.
  4. 4
    search — query itHybrid retrieval, fusing keyword and vector search, is the default. Switch with --strategy, and hand results to an agent with --json.

Convert PDF and Office documents to Markdown with docling or MarkItDown before adding them. See an integration example here. For installation, see the README on GitHub; to let an agent such as Claude Code do it, point it at the bundled SETUP.md.

Accuracy grows with configuration.

Choose how documents are split and how they are searched to fit the content and the use. Settings live in a profile (YAML), so you can switch and compare.

Four chunking strategies

General-purpose recursive, heading-aware markdown_recursive, block_aware to keep tables and code intact, and parent_child to match on children and return parents.

Four retrieval strategies

Keyword (BM25), vector (semantic), hybrid fusing the two (default), and parent_child. Switch per query with --strategy.

Contextual retrieval

Each chunk gets document-level context from a local LLM before embedding, so searches that a bare fragment would miss are found. Follows Anthropic's Contextual Retrieval approach.

Reranking

A CrossEncoder reorders the top candidates. Helps when the right passage is retrieved but ranked too low.

Evaluation and inspection

Measure retrieval quality with mrag eval, and look at chunk bodies, generated context and section hierarchy with mrag inspect.

Strong in Japanese

Supports a Japanese morphological tokenizer. The multilingual bge-m3 model is the default for embeddings.

Built by agents, used by agents.

mrag is designed to be operated by AI agents.

Agents build it, guided by SKILL.md

Point Claude Code or a similar agent at the bundled SKILL.md and SETUP.md and it handles installation, knowledge-base creation and accuracy tuning on its own.

# Example prompt for Claude Code
> Create an mrag project at ./my-kb from the
  Markdown files under ./documents/

Expose it as an MCP server

mrag mcp turns a project into a read-only MCP server, so Claude Code, LM Studio and other clients can call search as a tool. Supports stdio and Streamable HTTP.

# inside an indexed project
mrag mcp
# tools: search / list_documents / inspect_*

External knowledge for Dify

mrag serve provides an endpoint compatible with the Dify External Knowledge API, so a Dify chatbot can query a local knowledge base. A native REST API is also available.

mrag serve --host 0.0.0.0 --port 8000
# POST /retrieval  (Dify External Knowledge API)

Bundle multiple knowledge bases

mrag registry gathers several knowledge bases into knowledge_registry.yaml. Agents decide which base to search before searching. A foundation for agentic RAG.

mrag registry generate ./knowledges
# knowledges/kb-manual, kb-spec, kb-rules ...

  • Trying it right now

    When you want to run RAG on the documents in a folder today and see whether it helps, without waiting for contracts or infrastructure.

  • Documents that can't leave the company

    When confidential documents must stay on a PC or an on-premises server while still being usable by generative AI.

  • Giving agents domain knowledge

    When you want Claude Code, Dify, LM Studio or another agent to have knowledge specific to your work, delivered over MCP or an API.
